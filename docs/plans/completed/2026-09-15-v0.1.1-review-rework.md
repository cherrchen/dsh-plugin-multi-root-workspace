# v0.1.1 评审返工（PR #1）

> 编号口径：本计划是 `v0.1.1` 硬化批次（H1–H4）**发版前**的评审返工，不新增批次编号；批次总账见[路线图](../active/2026-09-12-multi-root-workspace.md#进度总账)。

## Goal

把 PR #1（`fix/v0.1.1-hardening` → `main`，head `507c954`）评审提出的 5 项发现（2 项 P1 + 3 项 P2）在发版前全部修掉，每项各带一个「修复前红、修复后绿」的回归测试。终态：

1. `src/registry.ts` 的 authority 拆除顺序成为可断言的不变量（排空在飞 mutation → close domain → release lease，且与 acquisition 不交错）；
2. 附加根的中间目录指令文件能真正到达模型；
3. `DSH_MULTI_ROOT_COMPAT=warn` 只放宽 `unsupported`；
4. `@deepseek-ai/dsh-llm` 与 `@deepseek-ai/dsh-agent-instructions` 两个可选 peer 的加载时机与失败语义明确；
5. `pnpm verify:all` 与 `pnpm docs:check` 全绿。

## Background

head `507c954` 上的五项发现（原文位置即修复前位置）：

| 编号 | 位置 | 问题 |
|---|---|---|
| P1-1 | `src/registry.ts` `releaseAuthority()` | 释放内核 lease **先于**关闭 domain，且未串入 store-wide authority 转场队列、未与每主根 mutation 队列同步。继任者可能在一次 `table.put()` 落盘之前拿到 lease 并打开一份缺了该次写的快照；一次在飞 acquisition（已拿到 lease、正处在 `openDomain()` 内）还可能在拆除之后完成，泄漏一个新打开的 domain + lease（没有任何人会再去关它） |
| P1-2 | `src/instructions.ts` `planRoot()` | 触碰 `<root>/a/b/file` 只把 `<root>/a/b` 加入被考察目录。discovery 虽然上报 `<root>/a/AGENTS.md`，但「目录必须精确等于本次考察目录」的过滤把它丢掉，而 `<root>/a` 从未被考察 → **中间目录的指令永远到不了模型** |
| P2-3 | `src/compat.ts` `assertSupportedInstallation()` | `warn` 放宽**所有**非 `supported` 判定，包括 `mixed` / `incomplete`，于是 `apply()` 会在混装 / 缺包的树上发布 `multiRootCompat`，授权放宽行随之启动 |
| P2-4 | `src/instructions.ts` | `import { createUserMessage } from '@deepseek-ai/dsh-llm'` 是对 optional peer 的**静态值导入**；`src/index.ts`（barrel，也就是 carrier loader 行挂载的模块）re-export 了 `instructions.ts`，因此零附加根的最小组合在加载 carrier 行时就失败 |
| P2-5 | `src/compat/agent-instructions.ts` `instructionsApi()` | `try { … } catch { return null }` 把「包不存在」与「包存在但求值失败（例如传递依赖缺失）」混为一谈，且 `null` 被缓存 → 整个进程静默不再投递附加根指令 |

P1-1 的落盘顺序依据是上游 `DomainImpl.close()` 的契约：立刻拒绝新写 → 排空已入队写 → 释放 backend unit，因此「先 close domain 再 release lease」是唯一正确的次序。详见 [ADR-0007](../../decisions/ADR-0007-registry-authority-lease.md)、[ADR-0009](../../decisions/ADR-0009-dsh-compat-contract.md)、[ADR-0010](../../decisions/ADR-0010-additional-root-instruction-scope.md)。

## Design

### 1. authority 拆除：排空 → close → release，且在转场队列内（P1-1）

`releaseAuthority()` 先置 `private disposed = true`，随后**整个拆除**都在 `serializeAuthority`（store-wide authority 转场队列）内跑：

```text
disposed = true
  ↓（进入 authority 转场队列）
fail closed：table = undefined、authorityState = { kind: 'contended' }
  ↓
drainMutations()：await Promise.allSettled([...chains.values()])
  ↓
withdrawPublished()
  ↓
domain.close()
  ↓
lease.release()
```

- **顺序是不变量本身**：lease 是「介质归我」的凭据，它必须比本进程最后一次写活得更久，包括 `close()` 自己会排空的那些已入队写。若继任者在 release 与某次 `put()` 之间拿到 lease 并打开介质，它读到的快照就缺了那次 mutation。
- **fail closed 在最前**：拆除期间不再有新 mutation 被接纳（之后被接纳的会在 `requireTable()` 里失败，这是设计）。
- **整个拆除走转场队列**：必须与 acquisition 互斥——一次 `refresh()` 若在 fiber 拆除时仍在飞，不能以「打开一个永远没人关的 domain + lease」收尾（这正是修复前用例 2 的红）。
- `ensureAuthority()` 的串行 job 首行 `if (this.disposed) return`：disposed fiber 再也不会打开新介质；在飞 acquisition 由同一次拆除收尾。
- 旧实现里「lease 在首个 `await` 之前释放，好让未被 await 的 disposer 仍能及时解锁」的注释已删除，因为它描述的正是要被修掉的顺序（`ctx.fiber.dispose()` 会 await 这个 disposer）。

见 [ADR-0007](../../decisions/ADR-0007-registry-authority-lease.md) 决策 2 与文末「返工补充（2026-09-15，PR #1 评审）」。

### 2. 被触碰路径的每个祖先目录（P1-2）

`planRoot()` 对被触碰路径的**父目录及其每个祖先目录（直到该附加根）**各考察一次：上游 discovery 是向上走的，会**上报** `<root>/a/AGENTS.md`，但精确目录过滤只保留「本次考察目录」的候选，所以 `<root>/a` 必须自己成为一次考察的起点，中间目录的规则才可能到达模型。`delivered` 目录的入队逻辑不变：一个已投递 nested 文件所在的目录本就会被逐步考察，其祖先在投递它的那一步也已被考察。

见 [ADR-0010](../../decisions/ADR-0010-additional-root-instruction-scope.md) 决策 1 与文末返工补充。

### 3. `warn` 只放宽 `unsupported`（P2-3）

```ts
if (enforcement === 'enforce' || report.verdict !== 'unsupported') throw new DshCompatUnsupportedError(report)
```

- `unsupported` = **一致**但在 allowlist 尚未列名的树 —— 升级车道唯一要探测的形状，`warn` 只放宽它。
- `mixed` / `incomplete` 描述的是契约**根本无法判定**的安装（一半的 sandbox 可能已经在另一半不再产出的形状上验证过，或必需包缺失），两种模式都拒绝。
- `throw` 发生在 `ctx.logger.warn` 之前，因此 `mixed` / `incomplete` 下 `apply()` 直接失败、门禁关闭。

见 [ADR-0009](../../decisions/ADR-0009-dsh-compat-contract.md) 决策 5。

### 4. 可选 peer 按需加载（P2-4）

新增 `src/compat/llm-message.ts`：`createInstructionMessage(input)` 在**真正要构造消息**时才 `await import('@deepseek-ai/dsh-llm')`，peer 缺失时抛带诊断的 `Error`；`src/instructions.ts` 只保留被擦除的 `import type { UserMessage }` 并调用该适配器；barrel 导出 `createInstructionMessage` 与 `InstructionMessageInput`。

不变量：**可选 peer 一律按需加载，不得静态值导入** —— barrel（carrier loader 行挂载的模块）的加载期依赖集合必须等于必需包集合，否则一个从不会构造消息的最小组合会在加载 carrier 行时就失败。

见 [ADR-0009](../../decisions/ADR-0009-dsh-compat-contract.md) 决策 4。

### 5. 「包不存在」与「已安装但求值失败」必须分开（P2-5）

新增导出 `isPackageInstalled(specifier)`：用 `createRequire(import.meta.url).resolve(specifier)` 探测可解析性（与 `src/compat/dsh-version.ts` 的 `readInstalledVersion` 同一模式），只有 `MODULE_NOT_FOUND` / `ERR_MODULE_NOT_FOUND` 才算「不存在」；其余解析失败留给真正的 `import()` 判定。

`instructionsApi()` 只在包**真的缺失**时返回 `null`（→ `undefined`）并缓存；「已安装但求值失败」（传递依赖缺失、构建损坏）照常抛出并传播——缓存 `null` 会让整个进程在余下的生命周期里静默不再投递附加根指令。

见 [ADR-0009](../../decisions/ADR-0009-dsh-compat-contract.md) 决策 4。

## Implementation

### A. `src/registry.ts`（P1-1）

- 新增 `private disposed = false`（字段区，`loggedContended` 附近）。
- `ensureAuthority()` 的串行 job 首行加 `if (this.disposed) return`。
- `releaseAuthority()` 重写为上文顺序，并删除已不成立的那句旧注释。
- 新增 `private async drainMutations()`：`await Promise.allSettled([...this.chains.values()])`，等待所有已入队 / 运行中的每主根 mutation。

### B. `src/instructions.ts` `planRoot()`（P1-2）

### C. `src/compat.ts`（P2-3）

`assertSupportedInstallation()` 的判定与注释按 §3 收紧；警告文本、`apply()`、`MultiRootCompatService` 均不动。

### D. 可选 peer（P2-4 / P2-5）

## Risks

| 风险 | 处置 |
| --- | --- |
| A 的用例用 fake `storageDomain` 而非真实 backend | 要断言的是「落盘顺序 + lease 与 domain 的释放次序」这一可观测不变量（第二个 DSH 进程看到的就是它）；真实 backend 的等价行为由既有 `tests/registry.spec.ts`（重启读回）与 `tests/registry-multiprocess.e2e.ts`（真进程接管）覆盖 |
| win32 同进程第二次 `acquire` 可能不报争用 | 只有第 2 例依赖「泄漏的 lease 仍被持有」来区分修复前后，必要时按平台 `runIf` 跳过；第 1 例三条断言不依赖同进程争用，全部保留 |
| `warn` 收紧影响升级车道 | 有意为之：只有「一致但未列名」的候选树能进 `warn`。候选树若报 `mixed`，按 ADR-0009 原意那是宿主侧混装，必须先对齐版本，**不得**放宽检查 |
| `isPackageInstalled` 依赖 `createRequire().resolve` 的语义 | 与 `src/compat/dsh-version.ts` 的 `readInstalledVersion` 同一模式，且该模式在 boot 时（bundled `lib/`）已被 smoke 证明可用，不引入新的构建期风险 |
| 抛错的 mock factory 若不表现为 `import()` rejection（P2-5 用例） | 改为 async factory 内 `await import()` 一个不存在的包再抛；两者都不生效时只保留 `isPackageInstalled` 的两条单测——**不得**为了迁就 mock 把 `instructionsApi()` 的失败重新吞掉 |
